# 01 — 将 Matplotlib Prefab 重构为单栏单图 Skill 库

状态：待执行的 handoff 计划。本文件不代表代码已经实现。

## 1. 目标与交付边界

将当前以 notebook 和静态网页为主的 Matplotlib Prefab 重构为面向 coding agent 的科学图表 skill 项目。首阶段实现一个入口 skill，支持单栏、单面板的折线图和柱状图，让 agent 能根据输入数据生成尺寸一致、文字清楚、可复现且经过检查的图表。

本阶段重点是搭好可运行的框架、完整工作流和两类模板。尺寸、字号、线宽、配色等数值均为暂定值，由仓库所有者后续手动调整并 finalize。不要把暂定审美值写成论文或会议的强制标准。

明确不做：双栏图、多面板图、散点图、热图、3D 图、直方图、堆叠／分组柱状图、双轴、误差条、复杂统计处理、会议特定 profile、交互式图表、插件市场发布。柱状图指离散类别与数值的比较，不是直方图。首版使用线性坐标。

允许实现者根据可运行性小幅调整内部模块划分，但应保持：一个自包含的 skill、一个参数真源、两种模板、一个渲染入口和可复用检查逻辑。不要先构建插件系统、通用布局引擎或大规模 Python 包层次。

- SKILL.md：触发范围、核心流程、如何运行脚本、何时读取引用文件、产物与验收要求。保持精简，不复制完整参数表或 Matplotlib 教程。
- references：数据契约、设计决策、参数含义和适用边界。
- profile：所有可调样式初值的唯一来源。示例和模板不得另藏一套默认字号或颜色。
- templates：只负责把已验证的数据绘制成对应的 artist；使用公共样式与输出逻辑。
- scripts：执行确定性的数据验证、profile 解析、渲染、导出与检查。复制 skill 目录后应仍可使用，不能依赖 legacy 或仓库根目录的私有模块。
- examples：至少各提供一个不依赖旧版 `.npy` 数据的可运行例子。
- pyproject.toml：声明实际需要的运行／开发依赖和测试设置；暂不发布软件包。

## 5. 输入与参数契约

以 JSON 作为最小可复现输入，暂不实现 CSV 自动推断。Agent 可先把用户数据整理为此格式，但不得静默改变其含义。

共同字段至少包含：schema_version、kind、x_label、y_label；可选 title。每个字段类型、默认行为和错误条件写在 input-schema.md。

- line：一个数值 x 数组，以及一个或多个具名数值 y 序列；x 与每个 y 等长，系列名称唯一。保留输入顺序，不静默排序、平滑或聚合。
- bar：一个唯一类别名数组和一个等长数值数组，单个系列，垂直柱状图；允许负值，显示零基线且纵轴范围覆盖零。不要把柱状图误实现为 histogram。
- 两者均拒绝空数据、不匹配长度、非数值或非有限值；错误信息指出字段和原因，不输出成功报告。
- 对未支持的 kind、布局或未知字段给出清楚错误，避免用户拼错参数后静默忽略。
- 字符串中的标签保持用户原意；数学文字的支持方式明确记录。

CLI 的调用形状建议为：

```sh
python skills/scientific-figures/scripts/render.py \
  --spec examples/line.json \
  --output-dir .tmp/figure-preview/line
```

允许通过 `--profile <path>` 指定用户修改后的完整配置文件；本阶段不实现多层继承和复杂样式叠加。文档命令应适配实际选择的 Python 环境管理方式。

## 6. 暂定 single-column profile

配置文件需包含版本与 `status: provisional`。以下均是项目初始选择，不是投稿标准：

| 项目 | 初始值／策略 |
| --- | --- |
| 图宽 | 85 mm |
| 高宽比 | 0.618；由宽度和比例计算高度，避免重复保存冲突值 |
| 轴标签 | 9 pt |
| ticks、legend | 8 pt |
| 可选标题 | 10 pt |
| 数据线 | 1.2 pt |
| 坐标轴与刻度线 | 0.6 pt |
| marker | 4 pt，形状与颜色绑定系列 |
| 默认字体 | DejaVu Sans；字重 normal |
| 普通文字 | 正体；数学变量允许按数学排版规则使用斜体 |
| 背景 | 白色 |
| 分类色 | `#4477AA`, `#EE6677`, `#228833`, `#CCBB44`, `#66CCEE`, `#AA3377` |
| 输出 | PDF 成品和 300 DPI PNG 预览 |

补充规则：

- 所有字号与线宽按最终物理尺寸解释；DPI 仅决定栅格分辨率。
- 默认不要求系统安装 LaTeX。数学标签可使用 Matplotlib mathtext；本阶段不承诺与某论文模板完全一致。
- 字体不可用或缺字必须体现在检查结果中。不要静默把缺字方框当成成功；中文可通过用户配置字体支持，本阶段不自动下载或捆绑字体。
- 折线图通过颜色加线型／marker 区分系列。超过预设容量时给出可理解的处理结果，不无声循环成不可区分的样式。
- 单系列柱状图默认同色，不为每个类别赋予无意义的不同颜色。
- 标题默认省略。折线图单系列且无歧义时可省略 legend；多系列必须可辨认，处理规则写清楚。
- 最大主刻度数量、柱宽、网格透明度和留白等需要的参数也集中放在 profile，采用合理初值。
- 全局样式使用局部上下文，避免执行一次绘图后污染后续图形。

## 7. 渲染与交付流程

1. 验证数据契约与 profile，拒绝非正尺寸等无效参数。
2. 解析最终画布尺寸、字体、色板与 artist 样式。
3. 选择 line 或 bar 模板，创建且仅创建一个面板。
4. 使用 Matplotlib 布局机制安排标签与留白。不要同时叠加相互冲突的布局策略。
5. 导出固定物理尺寸的 PDF 和 PNG。默认避免 `bbox_inches='tight'` 改变画布尺寸；若实现使用裁切，必须另行证明最终尺寸仍满足配置。
6. 运行确定性检查，生成 `report.json`。同时保存解析后的 profile 和输入快照，使生成结果可复现。
7. Agent 实际查看 PNG 预览：文字是否清楚、图例是否遮挡数据、线型与颜色是否可分辨、布局是否拥挤。若环境无图像查看能力，明确记录视觉检查未完成。
8. 根据明确问题做必要修正并重新导出；不自动更改数据，不无限循环。建议最多两轮自动修正，仍存在的问题如实报告。

用户一次请求可以在内部经历渲染与修正。不要声称一次成功执行脚本即达到最终美术标准。

输出目录至少包含 `figure.pdf`、`figure.png`、`spec.json`、`profile.resolved.json` 和 `report.json`。复现命令引用交付的输入和 profile；报告记录实际使用的 Matplotlib 版本与字体。对已有输出目录的覆盖行为需明确，不覆盖无关文件。

## 8. 检查能力与真实边界

首版检查覆盖：

- 实际画布尺寸与 profile 一致，PNG 像素尺寸符合 DPI，允许像素取整误差。
- 实际只有一个 axes 面板。
- 非空文字的字号、实际字体选择与 profile 匹配，记录缺字警告。
- 关键文本边界是否超出画布；明显的 tick 标签互相碰撞可作为告警。
- 柱状图的零基线与范围约束；折线的数据点数量与输入一致。
- 两种输出均存在且可读取。

可以把导出文件尺寸解析放在测试中实现，不必为了运行时检查引入重型 PDF 依赖。报告字段明确区分检查通过、告警、失败、未检查。尤其 `visual_review` 默认是未检查，不能由渲染脚本自动填成已通过。

边界框检查是启发式的；不要将有意重叠的图形元素都判为错误，也不要声称能完全检测图例遮挡或科学语义错误。数据准确性与视觉可读性都要评估，但首版不做通用统计正确性验证。

## 10. 验收要求

必要的行为测试与人工／Agent 视觉检查：

- 两份标准示例都可从文档命令生成 PDF、PNG、输入快照、解析配置和检查报告。
- 折线多系列的数据未被重排，样式可区分，标签和 legend 可读。
- 柱状图类别顺序保持，正负值案例正确显示，纵轴包含零。
- 长标签、缺失字体／缺字、无效输入、过多系列有明确结果，不误报全通过。
- 修改一份 profile 的字号和线宽后，两类图均使用修改值，无模板硬编码覆盖。
- PDF 的物理尺寸和 PNG 尺寸符合配置；重新运行相同 spec/profile 的数据与布局可复现，不要求时间戳或字节完全相同。
- 将 skill 目录复制到临时目录后，仍能用外部传入的 spec 运行，不依赖仓库根工作目录、legacy 或 notebook 状态。
- 验证入口 skill 的 frontmatter、资源链接和运行命令；若环境有 skill 校验工具则使用。结构校验不代替实际绘图验证。

测试重点是这些可观察行为。不要编写只匹配文档措辞或只证明常量被定义的测试。首版不要求跨平台像素级金图匹配，也不为美术质量输出虚假的自动评分。
